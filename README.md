# Серверная часть веб-приложения для планирования семейного бюджета

Курсовой проект: **серверная часть** веб-приложения для совместного учёта доходов и расходов, планирования лимитов по категориям и анализа финансов семьи. Реализована на **Django** по паттерну **MVT** (Model — View — Template).

**Нормативная база курсового проектирования:** инструкция по организации и проведению курсового проектирования СМКО МИРЭА **7.5.1/04.И.05-18**. Оформление пояснительной записки — в соответствии с **ГОСТ 7.32-2017**.

## Предметная область (кратко)

Пользователи объединяются в **семью**: один участник — **глава** (управление составом, ролями, расширенные права), остальные — **член семьи** или **наблюдатель** (ограниченный набор действий). Для семьи ведутся общие **категории** доходов/расходов, **транзакции** с привязкой к автору, **бюджеты** по категориям и месяцам, **отчёты** и **импорт/экспорт CSV** (в рамках назначенных прав).

Пользователь без семьи может вести учёт в **личном** режиме до создания или вступления в семью.

## Основной функционал

- Регистрация и вход (`django.contrib.auth`)
- Создание семьи, приглашение участников, смена ролей, выход из семьи
- Транзакции: список с фильтрами (даты, категория, участник), создание, удаление (в семье — по правилам для главы и участников)
- Категории и бюджеты с проверкой прав (`can_set_budget`, `can_manage_family` и др.)
- Страница отчётов, экспорт и импорт транзакций в CSV
- Группы Django: «Глава семьи», «Член семьи», «Наблюдатель» (миграция `0004_create_default_groups`)

## Установка и запуск

### 1. Клонирование и переход в каталог

```bash
git clone <URL репозитория>
cd kursach_6_backend
```

### 2. Виртуальное окружение

```bash
# Windows
python -m venv venv
venv\Scripts\activate

# macOS / Linux
python3 -m venv venv
source venv/bin/activate
```

### 3. Зависимости

```bash
pip install -r requirements.txt
```

### 4. Переменные окружения (при необходимости)

В корне проекта можно разместить файл `.env` (подключается через `django-environ` в `family_finance/settings.py`): `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS` и др.

### 5. Миграции

```bash
cd family_finance
python manage.py migrate
```

### 6. Суперпользователь (админ-панель и тестовый вход)

```bash
python manage.py createsuperuser
```

### 7. Запуск сервера разработки

```bash
python manage.py runserver
```

Приложение: [http://127.0.0.1:8000/](http://127.0.0.1:8000/).

## Модели данных (логический уровень)

- **Family** — семья; дополнительные права на уровне модели (`can_manage_family`, `can_view_family_reports`)
- **FamilyMember** — связь пользователя с семьёй, флаг главы (`is_head`)
- **Category** — категория дохода/расхода, привязка к семье и/или пользователю (личный режим)
- **Transaction** — сумма, дата, описание, категория, пользователь-автор; кастомные права (`can_delete_any_transaction`, `can_import_export`)
- **Budget** — лимит по категории и месяцу, семья/пользователь; право `can_set_budget`

Связи и ограничения задаются в моделях и миграциях Django ORM.

---

## Паттерн MVT в проекте

- **Model** — описание сущностей и миграции в `core/models.py`
- **View** — обработка запроса, выборка из БД, проверка прав, вызов форм и `render()` / редиректы в `core/views.py`
- **Template** — HTML с тегами Django и контекстом в `core/templates/`

Маршрутизация: `family_finance/urls.py` подключает `core.urls`.
